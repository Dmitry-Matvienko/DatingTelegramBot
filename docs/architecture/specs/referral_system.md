# Спецификация: Реферальная программа (Referral System)

## 1. Назначение подсистемы
Подсистема реферальных ссылок предназначена для органического привлечения новых пользователей в бота DatingBot. Взамен на приглашение новых пользователей создателю ссылки начисляются дни продвижения анкеты в топе поиска (Top Boost) с накопительным эффектом (+3 дня за каждого нового пользователя).

---

## 2. Пользовательский интерфейс и сценарии (UX/UI)

### 2.1. Главное меню
В главное меню (`MainMenuKeyboards`) добавлена кнопка:
- **`Menu_Referral`**: «🎁 Реферальная программа» (RU, UK, EN, HI, PT, ID).
- Также поддерживаются текстовые команды `/referral` и `/ref`.

### 2.2. Описание программы и инлайн-кнопки
При переходе в раздел реферальной программы отображается текст:
```html
Приведите новых пользователей, и взамен мы будем продвигать вашу анкету в топы.

1 новый пользователь приведенный вами - 3 дня в топе поиска(накопительный эффект)
```
И две Inline-кнопки:
- **«📋 Мои реферальные ссылки»** (`ref_my_links`)
- **«➕ Создать ссылку»** (`ref_create_link`)

### 2.3. Кнопка «Мои реферальные ссылки» (`ref_my_links`)
- Если у пользователя еще нет сгенерированной ссылки:
  - Отправляется моноширинное сообщение: `<code>У вас еще нет ссылок</code>` (для быстрого копирования в буфер обмена по клику).
- Если ссылка уже создана:
  - Отправляется моноширинная ссылка: `<code>https://t.me/BotUsername?start=ref_XXXX</code>`.

### 2.4. Кнопка «Создать ссылку» (`ref_create_link`)
- У одного пользователя может быть **строго одна реферальная ссылка**.
- Если ссылка уже существует — возвращается существующая ссылка.
- Если ссылки нет — генерируется новая уникальная ссылка с префиксом `ref_` и 8 алфавитно-цифровыми символами.
- Выводится сообщение:
  ```html
  Вот ваша реферальная ссылка, будь всегда в топе

  <code>https://t.me/BotUsername?start=ref_XXXX</code>
  ```

## 3. Обработка перехода по реферальной ссылке

### 3.1. Запуск бота по ссылке
Когда новый пользователь переходит по ссылке, Telegram отправляет команду:
`/start ref_XXXX`.

### 3.2. Правила фиксации реферала
Реферальный переход засчитывается только если:
1. Пользователь является новым (ранее не был зарегистрирован / `ReferredByUserId == null`).
2. Пользователь не пытается активировать собственную ссылку (`referralLink.UserId != newUser.Id`).
3. Реферальная ссылка существует в базе данных.

### 3.3. Начисление бонуса и уведомление
При успешной фиксации:
1. `ReferralLink.InvitedCount` увеличивается на 1.
2. В таблицу `ReferralRecords` добавляется запись с `ReferrerUserId`, `ReferredUserId` и `ReferralLinkId`.
3. Рефереру продлевается нахождение в топе (`UserProfile.TopBoostUntil`):
   - Если буст не был активен: `DateTime.UtcNow + 3 дня`.
   - Если буст уже активен: `TopBoostUntil + 3 дня` (накопительный эффект).
4. Рефереру в Telegram отправляется сервисное уведомление на его выбранном языке интерфейса:
   ```html
   Поздравляю! По вашей ссылке перешёл новый пользователь. Ваша анкета будет в топах на 3 дня дольше. Итого: N дн.
   ```

## 4. Доменные сущности и схема БД

### 4.1. `ReferralLink`
- `Id` (`Guid`, PK)
- `UserId` (`Guid`, FK к `Users`, Unique)
- `Code` (`string(50)`, Unique, индекс `IX_ReferralLinks_Code`)
- `InvitedCount` (`int`, default: 0)
- `CreatedAt` (`DateTime`, UTC)
- `UpdatedAt` (`DateTime?`, UTC)

### 4.2. `ReferralRecord`
- `Id` (`Guid`, PK)
- `ReferralLinkId` (`Guid`, FK к `ReferralLinks`)
- `ReferrerUserId` (`Guid`, FK к `Users`, индекс `IX_ReferralRecords_ReferrerUserId`)
- `ReferredUserId` (`Guid`, FK к `Users`, Unique индекс `IX_ReferralRecords_ReferredUserId`)
- `CreatedAt` (`DateTime`, UTC)

### 4.3. Поля в `UserProfile` и `User`
- `UserProfile.TopBoostUntil` (`DateTime?`) — дата и время окончания буста.
- `User.ReferredByUserId` (`Guid?`) — внешний ключ на пригласившего пользователя.
